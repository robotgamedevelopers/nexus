# models: the TLA+ specifications of nexus

Every state machine in nexus has a TLA+ module here (`Overlay.tla`, when the overlay shows and hides, among them). TLC checks each module on a small instance, with reversed witnesses, and the code is bound to the module: the code's own random walk writes traces, and TLC checks that each trace is a behaviour of the module.

This file covers the window's model. The server's durable state has its own directory: `store/` (its README), the layout of the journal under `src/store/`.

## What is modelled

`Window.tla` is the state the window owns, `nexus::Model` in `src/model.h`:

- `friends`: one tab per friend, fixed when the model is built. A friend is named by its place in that list, its id (`Tab::id` in the code), which never changes;
- `order`: the tabs' order, each position's tab id. A friend tab's id is its friend's; a terminal tab's id is one handed out by `AddTerminal`. Positions count from 0, as in the code;
- `nextId`: the next id `AddTerminal` hands out. Ids only grow, so no id is ever used twice;
- `active`: the active tab's position, 0 when there are no tabs;
- `history`: the selection history, `Model::selection_history()`: the ids of the tabs selected, most recent last, each once, open tabs only. The tab active at the start is its first entry; select and add put their tab's id at its end, and close takes the closed tab's id out. Closing the active tab makes the last id left in it active, the tab selected before it, whatever its kind; with none left, the rule before it (the tab now at its position, or the last). It is kept for the run only;
- `transcript`: each friend's entries, kinds `Person`, `Friend`, `Notice`;
- `draft`: each friend's unsent text;
- `queue`: each friend's prompts held for later, oldest first. The queue is apart from the transcript: it mirrors the queue the server holds, and its oldest prompt leaves it only by `TakeQueued`, when the server delivered it (the window's mirror's call; `Link.tla` models the delivery).

Transcripts, drafts and queues are indexed by friend, so they go with the tab when it moves; operations take positions, as the code's do, and act on `At(i)`, the friend at position i. The actions are the model's operations, with the arguments a caller passes, in range and out of it: `SelectTab(i)`, `SetDraft(i, t)`, `Send(i)` (the draft becomes a `Person` entry at the end of the tab's transcript), `Queue(i)` (the draft goes to the end of the tab's queue), `TakeQueued(i)` (the oldest prompt of the tab's queue leaves it), `AppendEntry(i, e)`, `MoveTab(from, to)` (the tab at `from` ends at `to` and the tabs between shift by one; refused when the two positions lie in different zones), `AddTerminal` (a terminal tab at the end, made active), `CloseTab(i)` (removes the tab at i, only a terminal). A refused operation changes no model state.

Each tab kind has a zone (`Zone`): the sprint tab 0, friends 1, terminals 2. The order runs by zone, and a move stays inside its zone. The sprint tab is there when the constant `Sprint` is TRUE (the window's model always has it): it is made at the start in position 0 with id `SprintId` (N, the first after the friends'), alone in zone 0, so nothing moves before it, it never moves, and close refuses it. A terminal and the sprint tab hold no transcript, draft or queue: send, queue, set_draft and append refuse them.

`MoveTab` carries the code's index arithmetic, not only its result: the order is `Moved` (the code's `std::rotate`) and `active` is `MovedIndex` (the code's three-way adjustment of `active_`). The properties then state what that arithmetic must give in terms of friends: the same friend active, every friend kept once, the others in their relative order.

`last` is a history variable, not model state: the operation just performed, its arguments and the value it returned. The action properties are stated through it, and a code trace's return values are checked against it.

All-whitespace means every byte is an ASCII space, tab, newline, vertical tab, form feed or carriage return; the empty draft is all whitespace. The spec does not compute this: the constant `Blank` names the drafts that are all whitespace, and each instance lists them.

### Instances

`MCWindow.tla` gives the constants values and bounds transcript and queue length (`MaxLen`, a state constraint). The drafts are `""`, `" "`, `" \t\n"` and `"hi"` (one witness adds `"yo"`, so that an order of queued prompts shows); the appended entries are a friend's reply, an empty notice and an all-whitespace `Person` entry (append takes any entry). The checked instances use fewer (`MCDrafts3`: `""`, `" "`, `"hi"`; on three tabs `MCAppendEntries3`: the reply only), because every order multiplies the states: the spec does not compute whitespace, so a second all-whitespace draft adds only states. Positions run to one past the last tab, for both of a move's. TLC tells states apart by the model variables alone (`VIEW ModelView`), which is sound because no action reads `last` and no property reads it unprimed.

Every order of the selection history is a state of its own, so the history multiplies the instances with many tabs. The times are the studio's in a login session; CI's runners take about four times as long.

## The binding: code traces checked against the spec

`tests/model/trace_walk.cpp` drives the real `nexus::Model` with a seeded random walk (`trace_walk <seed> <steps> <friends> [--no-sprint] [--faulty | --faulty-queue | --faulty-move | --faulty-queue-cap | --faulty-send-trim | --faulty-send-dedup | --faulty-close | --faulty-sprint-move | --faulty-sprint-close | --faulty-close-fallback] <out.tla>`). The model starts with the sprint tab, as the window's does, unless `--no-sprint`. The random numbers come from the seed alone. Each step calls one operation (adding and closing terminals among them, at most three open), with positions in range and two past the last tab (a move draws both, so moves across zones are tried and refused), drafts that are empty, all whitespace (including tab, newline, vertical tab, carriage return and form feed), text with quotes and backslashes, and text with whitespace before, after and around it, and entries of every kind. Two kinds of step repeat the last accepted send or queue with the same text to the same tab (a `set_draft`, then the `send` or `queue`), so that equal sends follow each other and queues grow long; the walk prints the longest queue (dozens of prompts at 1000 steps). Every 25th step is followed by a `take_queued` at the same position, a step that draws no random number, so the other steps are as they were. The walk writes `WindowTraceData.tla`: the arguments' domains and `Trace`, one record per step, holding the operation, its arguments, the return value and the model's whole state after it: the order (each position's `Tab::id`), the selection history and, by position, each tab's kind, friend, draft, transcript and queue.

`WindowTrace.tla` instantiates `Window` with those domains. Each of its steps takes the `Window` action the record names, with the record's arguments, and the invariant `TraceMatches` requires the spec's state and return value to equal the code's: the order, the active position and the history equal, and the tab at each position holding the state of the friend the spec has there. A step whose arguments lie outside the spec's domains has no successor and TLC reports a deadlock. The property `WindowSpec` checks the whole behaviour against `Window`'s `Init` and `Next`, and every `Window` property is checked on the trace too.

The binding is shown to fail, ten times: `--faulty-close-fallback` walks a subclass whose `close_tab` of the active tab ignores the history and keeps the rule before it (rejected at the first close of an active tab where the two rules differ); `--faulty-sprint-move` walks a subclass whose `move_tab` takes the sprint tab among the friends, `--faulty-sprint-close` one whose `close_tab` closes it; `--faulty` walks a test-only subclass whose `send` accepts a draft that is all whitespace but not empty, `--faulty-queue` one whose `queue` also puts the draft in the transcript, `--faulty-move` one whose `move_tab` leaves `active` at the old position, `--faulty-queue-cap` one whose queue drops its oldest prompt past four, `--faulty-send-trim` one whose `send` strips trailing spaces, `--faulty-send-dedup` one whose `send` of the text just sent appends nothing, and `--faulty-close` one whose `close_tab` also removes a friend's tab. TLC must report `TraceMatches` violated at the first step where each fault shows.

## TabLabel.tla: a terminal tab's label across ssh sessions

`TabLabel.tla` is `nexus::TabLabel` in `src/remote.h`: one terminal tab's label. Once a frame the window observes the terminal: the remote label of its foreground process (the fleet machine its ssh reaches, its host if not a fleet machine, or none when the foreground is not ssh), the program's title, and `late`, whether the frame comes after the tail of the last session to end (the code compares the frame's time with that end plus `kSessionTailSeconds`). Its state is the code's members: `remote`, `before` (the title at the last observation outside sessions and masks), `after` (the title a session left), `masking` and `tail`; `last` records the observation. `Label(t)` is the label drawn when the title is `t`.

| Property | Kind | What it says |
|---|---|---|
| `TypeOK` | invariant | every variable has its type |
| `TailMasks` | invariant | a tail is part of a mask |
| `SessionNamed` | invariant | while a session is seen, the label is its remote label, whatever the title |
| `TitleShows` | invariant | outside sessions and masks, the label is the title |
| `SessionNamedAtOnce` | action | an observation of a session names it at once |
| `EndRestores` | action | the observation that sees a session end gives back the label from before it, whatever title it left |
| `TailRestores` | action | in the session's tail the label stays the one from before, whatever title arrives |
| `MaskEnds` | action | past the tail, the first title other than the one the session left is shown: the label never sticks |
| `BeforeIsOwn` | action | the label to return to only ever changes to a title observed outside sessions and masks |
| `BeforeIsLatest` | action | and every such observation takes it |

`TabLabel.cfg` checks them on two remote labels and three titles (295 states). Its witnesses: `WLabelNoMask` (a session's end shows the title it left; `EndRestores`), `WLabelMaskSticks` (the mask never lifts; `MaskEnds`), `WLabelBeforeAtStart` (the label to return to is the title at a session's first observation, which ssh may already have set; `BeforeIsOwn`), `WLabelNoTail` (no tail, so a last title read after the process is seen gone shows; `TailRestores`).

`tests/model/label_walk.cpp` (`label_walk <seed> <steps> <remotes> [--faulty-before] <out.tla>`) drives the real `TabLabel` with a seeded walk on a made-up clock (a frame or a pause a step): sessions start, run, switch and end, titles change, and frames fall inside tails and after them. It writes `TabLabelTraceData.tla`: one record per observation with its arguments, the code's state after it and the label the code draws for every title. `TabLabelTrace.tla` takes `Observe` with each record's arguments and `TraceMatches` requires the spec's state and every label to equal the code's; every `TabLabel` property is checked on the trace. Four traces run (seeds 1 to 3 on two remotes, seed 4 on three), and `--faulty-before`, which feeds the code an unrecorded observation before each session's first (the code then takes the label to return to from a title ssh may have set), must be rejected with `TraceMatches` violated.

## Link.tla: what nexus adds on top of mosh

`Link.tla` models the link between the windows and `nexus-server` (`src/sync`, `src/link`, `src/server`): what nexus puts on top of mosh's State Synchronization Protocol, not mosh. mosh is abstracted to the two things nexus relies on. Up, what reaches the server of a window's list is some range of it, which may repeat a range, come after a later one, or start past what the server has: `Deliver(c, first, last)` takes any range. Down, a window's receiver eventually holds the server's newest state, may skip states between, and never goes back to an older one (mosh numbers its states and keeps the newest): `Receive(c, j)` is window c receiving the server's j-th state, the same as before or a later one.

- Up: `acts[c]`, window c's actions, numbered from 1 (`sync::Actions`): a send, a queue or a stop naming a session id (held or not), a create for a friend copying no session or a given id, or an ensure for a friend; `applied[c]`, the server's `sync::Applier` for it; `done[c]`, a history variable, every number the server applied, in order. The Applier applies the numbers past `applied[c]` in a range, refuses one that starts past `applied[c] + 1`, and ignores one wholly applied.
- The server: `ses[i]`, the session with id i, its friend, or none (`NoSes`), over the ids 1 to `MaxSessions` (the hub's limit); `nextSid`, the next id the store mints, durable; `minted` and `skipped`, history variables: each id minted with the action that made it (the sessions of `Start`, there from before, by none), and each action applied that changed nothing. `tr[i]` and `q[i]`, each session's transcript and queue (`sync::Hub` over its store, durable); `op[i]`, its open entry, the friend's text still growing (`Hub::setOpen`, in memory only); `stops[i]`, a history variable, every stop applied naming the id, and whether it reached the responder (the drivers) or was refused because the server holds no such session. A send puts the prompt and a placeholder reply in the session's transcript, a queue the prompt in its queue, each only in a session the server holds; a stop changes no session. A create mints the next id for its friend unless the server is at its limit or the session it copies does not exist; an ensure does the same only when the friend has no session. The server's own steps: `Grow(i)`, in a session that has had something sent or queued, (an open entry is made, numbered, or grows), `Close(i)` (the open entry is closed into the transcript, all its text, and is gone), `Take(i)` (with no entry open, the queue's oldest prompt is delivered: it leaves the queue and is the person's entry in the transcript), `Restart` (the server starts again from its store, its sessions and its next id with it: every open entry is lost and its turn cut with a notice). `made` counts the open entries made, the grows and the restarts. Each change makes a new state in `snaps`: for each session held, its friend, its transcript's newest `W` entries from index `first` (`sync::tailOf`, by count; the byte budget is not modelled), then the open entry, which the tail does not count, so the newest closed entry always comes with it; and the whole queue.
- Down: `last[c]`, the state window c's receiver holds; `shown[c][f]`, the session friend f's tab shows (0 for none yet): the window's own choice, in its mirror (`Mirror::session`), the friend's first session (the lowest id) in the first state that holds one, kept from then on; `view[c][f]`, `vq[c][f]`, the tab's transcript and queue; `seen[c][f]`, its mirror: the transcript index it shows through; `live[c][f]`, the open entry the mirror holds apart from the transcript (`Mirror::open`). Receiving a state, the mirror appends a notice of how many entries left the tail before it saw them, then the closed entries it has not shown, stopping at the open entry, which it holds; and makes its queue the state's (the prompts the server took leave its head, `Model::take_queued`, and those queued since go at its end).

Entries are records: a prompt `[k |-> "P", text |-> <<c, n>>]` (action n of window c, sent, or queued and delivered), its reply `[k |-> "F", text |-> <<>>]`, the friend's grown text open `[k |-> "O", text |-> <<g, len>>]` and closed `[k |-> "G", text |-> <<g, len>>]` (the g-th open entry, of len pieces), the notice of a turn a restart cut, which lost open entry g, `[k |-> "X", text |-> <<g>>]`, a notice of m entries not shown `[k |-> "N", text |-> <<m>>]`.

Not modelled: mosh (sockets, crypto, fragments, timers, acknowledgements, its own correctness); the hub's limits on text and queues (a refused prompt becomes a notice in the transcript, which the mirror shows like any entry; the limit on sessions is `MaxSessions`); a session's harness, account, model and effort, and the actions that set them, which change no transcript or queue but for a refusal's notice (the hub's checks are unit-tested, by `hub_settings` and `hub_create_copies_settings`, and what a change does to the driver is `Supervisor.tla`'s); the turns themselves and what ends them (`Supervisor.tla`): here the server's own steps happen whenever their guards allow. So a restart cuts only a turn with an open entry; the code also cuts an open turn with no text yet, or whose text is all closed, and that notice is an entry the server appends like any other, which the properties on the transcript already cover. The binding stands a responder in for the drivers: the supervisor's take and stop are bound by `Supervisor.tla`'s trace check, while how `Drivers` turns its output into the hub's changes (the take first, then the effects, then the driver's state) is tested end to end by `friends_functional_queue`, `friends_functional_queue_unconfigured` and `friends_functional_stop`, not trace-checked.

How much is durable, and when (the decision behind `op`): the open entry is in memory only, and becomes a durable closed entry at its block's end (text-end, a tool line, the turn's done or cut, or the entry limit: one journal record per block, never one per delta). A restart loses at most the open block's text, and the restart's cut notice says the reply was cut; a closed entry is in the store once, and the mirror appends only closed entries, each index once.

## Supervisor.tla: a session's driver

`Supervisor.tla` models `src/server/supervisor.h`, the state machine `nexus-server` keeps per session: it starts the session's driver when a prompt waits, writes each prompt as the next turn, gathers the friend's text, stops a turn, and ends the driver (input closed, then TERM, then KILL, each after its grace period). The driver is the environment: any message of any kind, for the open turn or another, a line the server refuses, a pipe closing, an exit at any moment. A driver that reports `no-credential` (protocol rule 11) is ended once no turn is open, and no driver is started again until the person's next prompt. Deadlines are steps that may happen (no hello, no done after a stop, each grace while ending); a working turn has none. `Restart` is the server dying and starting again from what the store holds: the next turn number, the open turn, the last session id, the waiting prompts and the queue. `Shutdown` is the server stopping. The queue is the person's prompts held for later (Command-Enter), the hub's queue of the session; the waiting prompts are those a send left for the driver. `QueuePrompt` puts a prompt at the queue's end, and `Take`, after every event, moves the queue's oldest prompt to the waiting prompts once no turn is open and nothing waits, shown as the person's entry: one per turn, oldest first, each once. So a prompt queued with the friend idle goes at once, a sent prompt waiting goes before the queue, and a stop ends the turn and lets the next queued prompt go. Not modelled: the server also takes nothing while the friend has no driver configured (its drivers file lost it): the model's driver is always configured, and that guard only makes `Take` enabled less often, so every safety property still holds; `supervisor_unit_queue` and `friends_functional_queue_unconfigured` and `friends_functional_restart_unconfigured` test it. `Stop` ends what runs when it arrives: it writes one stop for the open turn, or, while the driver starts, cancels the turn about to begin (its prompt leaves the waiting prompts, never written, with a notice; the driver keeps starting for the next). One that finds the turn already stopping, or nothing running, changes nothing: no stop is kept for a later turn. `stops`, a history variable, records each stop written, and `asked` marks the step of the person's stop.

Invariants: `TypeOK`; `OneDriver` (at most one driver process, alive exactly when the phase says so); `OneTurn` (at most one turn open, only while a driver works on it); `TurnsIncrease` (a turn number is never reused, across driver and server restarts); `AtMostOnce` (each prompt is written to a driver at most once, ever); `WaitingSound` (a prompt waits only while the driver cannot take it, within the bound); `LimitHolds` (the failed-start count stays within its limit); `QueueSound` (the queue within its bound, each prompt in it once, and in it exactly while queued); `StopOnce` (at most one stop written per turn). Action properties: `StopForOpen` (a stop is written only for the open turn), `StopEndsWhatRuns` (a stop ends what runs when it arrives: the open turn, or while the driver starts the turn about to begin, its prompt cancelled and never written; finding the turn already stopping, or nothing running, it changes nothing), `NoLatchedStop` (a stop is written, or a turn cancelled, only in the step of the stop that found it running, so a stop that found nothing never touches a later turn), `TakesAtTurnEnd` (a queued prompt leaves the queue only at a turn's end, the oldest, one per turn, as the person's entry), `EffectsForOpen` (every entry of a turn is for the turn open before the step), `EndsAnsweredOrCut` (a turn ends by its done or by a cut with its notice), `TextKept` (gathered text goes into the session before the turn's closing notice), `StartsSound` (a driver starts only when not held back, and with `--resume` the last session id), `NoSendWithoutCredential` (no prompt is written to a driver that reported it has no credential), `WrittenWithSetting` (a prompt runs with the model and effort the session has when it is written: a change applies from the next turn), `SettingLeavesTurn` (a change of the model or effort never touches a turn in progress: no line written, no driver started, no turn opened or ended, no entry; an idle driver it must end is ended quietly), `NoSendOnOldAccount` (a prompt is written only to a driver started under the session's account as it is then), `AccountKeepsTurn` (a change of the account never ends a turn: the driver under the old account is ended once no turn is open, never counted as a failed start). Liveness: `Settles` (every prompt accepted is answered or cut, or waits while starting is held back or the server is stopping), under fairness for deadlines, the person's stop of a working turn (`StopWorking`: there is no deadline on one; a stop of a start is never assumed, so no prompt settles by being cancelled) and KILL.

A setting is a record of a model and an effort, each from `Models` or `Efforts` or `""` (the harness's default); `Accounts` are the accounts the person may choose besides the default, and `MaxSwitches` how many changes they make in all. A driver starts on the defaults, and `told` is what it has been told since: before a send, a `settings` line gives it each field where the session's differs, and it applies the line from that send on, a field left out staying as it is (`docs/driver-protocol.md`). That line cannot put a field back to the default, so a driver told a field the session has cleared is ended once no turn is open, like one under an old account, and the next starts on the defaults. Instances: `MCSupervisorSwitch.cfg`, the changes of model, effort and account, with two prompts, one failed start, no restart and one change (52,548 states, 20 s on four workers); `MCSupervisor.cfg`, two prompts, one waiting, two failed starts, one restart, one session id (26,302 states, 6 s on four workers); nightly, `MCSupervisorQueue.cfg`, three prompts, two waiting or queued, no restart (111,319 states, 33 s), `MCSupervisorWide.cfg`, three prompts (each sent or queued), three failed starts, two restarts, two session ids (1,117,970 states, 4 min 11 s on eight workers, so capped at 900 s), and `MCSupervisorSwitchWide.cfg`, `MCSupervisorSwitch.cfg` with two failed starts, a restart, an effort and two changes (1,359,356 states, 6 min 32 s on eight workers, capped at 900 s).

`SignIn` is the account's login arriving through the secret dialog (`docs/secrets.md`, `Supervisor::signedIn`): while starting is held back (`blocked`, after a `no-credential` or three failed starts) it lifts the hold and clears the failed-start count, as a prompt does, so what waits starts a driver without a restart or another prompt; with nothing held it does nothing. It counts as one of the person's changes (`MaxSwitches` bounds it), and the ghost `signin` marks the step so that `DownLeavesByWork` allows the cursor to leave down by it. The walk takes it on seeds that hold (2, 3 and 4 do). Per commit it has an instance of its own, `MCSupervisorSignIn.cfg`: two prompts, one failed start, no restart, nothing to change to, and one change, which is a sign-in or a change of the drivers file. The switch and place instances leave it out (`SignIns <- NoSignIns`, `MCSupervisor.tla`): spending their one change on a sign-in roughly doubled their run times, which left too little room under their 75 s caps. The nightly wide instances take it among their other changes.

## ClaudeDriver.tla: the Claude driver's turns

`ClaudeDriver.tla` models `drivers/claude/src/driver.ts`, the driver between the protocol (`docs/driver-protocol.md`) and one Agent SDK query. State: the credential check's `phase` (checking, ready, ended), whether the harness was started with a `--resume` id, the open turn and its `stage` (waiting behind the credential check or an unanswered interrupt, applying its settings, pushed into the query's input and still withdrawable, taken by the query), `stopping`, an open text block, an assistant's reported `failure`, `intFor` (the turn whose interrupt has not answered), the settings `pending` for the next send, the open turn's `carry` (not yet applied) and those `inUse`, and the last turn. History for the properties: the turns sent, the dones written per turn, what the last step wrote (`wrote`, kinds and turns), the latest settings received (`want`) and those at the open turn's send (`turnWant`), and whether the last step was a stop and of which turn (`act`).

The server is the environment (sends after the last done, stops for any turn at any time, settings, the end of input), and so is the query (the credential check's answer, including an API key, a failure, or a `--resume` id it does not know; reading a prompt; text, block ends, whole text blocks, tools; an assistant's error; the result, ok, error, or "no such session"; a refusal mid-turn (an API key in `init`, overage); the stream failing; an interrupt answered). A stop ends what runs when it arrives: a prompt not yet read is withdrawn and the turn ends at once, one the query runs is interrupted; a stop for a turn not open, or already stopping, changes nothing. The next turn's start waits behind an unanswered interrupt. A turn takes the settings received before its send; a stop before it began gives them back under any newer ones. A lost `--resume` id closes the old query (and its interrupt), ends any open text block, starts a new session with the settings in use, and either ends a turn being stopped or starts the turn again there after the new credential check.

Invariants: `TypeOK`; `OneDone` (each turn sent has no done while open and exactly one once closed); `StopNeverLater` (while an interrupt has not answered, no other turn's prompt is in the query). Action properties: `NoDoneInBlock` (what a step writes keeps text blocks whole: no tool or done inside one); `SettingsNeverChangeOpen` (no settings change under a turn whose prompt is in the query); `SettingsFromNextSend` (a turn's prompt goes in with exactly the settings received before its send); `StopEndsWhatRuns`; `NoLatchedStop`. Liveness under fairness of the driver's own steps and the query's answers: `EveryTurnEnds` (every turn sent gets its done unless the driver exits, which the server cuts: `Supervisor.tla`), `InterruptsAnswered`.

## Glide.tla: the sprint board's scrolling

`Glide.tla` models `nexus::GlideScroller` (`src/scroll_glide.h`), which animates the board's scroll for the keys and the mouse wheel. The page's scroll is `pos` in `0..Max`; the band drawn past an end is `over`. The motion is `mode`: `idle`, a `coast` easing to `target` (exponential decay), a `hold` running while an arrow is down, or a `spring` taking the band back to an end (critically damped). Time is frames of `Dts` ticks; a coast or a spring that has not settled by its cap (`CoastTicks`, `SpringTicks`) lands where it was going. The curves are abstracted: each frame moves the page any amount the right way, up to the target, so a curve that overshoots or turns back is caught by the properties. The actions are an arrow pressed (`Press`), its OS repeat (ignored), its release (`Release`; the window losing focus is a release too, as Prax sends a key-up for every held key on resign), another key (`Key(d)`: a page, an end), a notch (`Wheel(d)`), a trackpad's scroll or a press of the pointer (`Interrupt`), the page's own script scrolling (`Page(y)`), the board leaving the screen (`Hide`), and `Frame(dt)`.

| Property | Kind | Says |
|---|---|---|
| `InRange` | invariant | the scroll is in its range, the band under the view's height |
| `BandAtEnds` | invariant | the band only at an end, on its outer side |
| `ShowsItself` | invariant | while a motion runs, the page shows what the scroller last set |
| `SpringAtEnd` | invariant | a spring stays at its end and never swings into the page |
| `HeldOnlyPressed`, `HoldIsHeld` | invariant | only an arrow held down holds |
| `EventsKeepPlace` | action | an event never moves the page itself: what it starts moves from where the page shows |
| `NeverBack` | action | a coast or a hold, and every event during one, never moves the page back against its way (a retarget never jumps back) |
| `PadStops` | action | a trackpad's scroll or a click stops the motion and the hold |
| `Settles` | liveness | once input stops, the page comes to rest and nothing is held |

`MCGlide` is the instance: a page of 3, lines of 1 and keys of 2 or 3, 15,668 states in about 2 s.

| Witness | Broken | Rejected by |
|---|---|---|
| `WGlideJumpBack` | a key restarts the motion from where it began | `NeverBack` |
| `WGlideClampTop` | no clamp at the top | `InRange` |
| `WGlidePadKeeps` | a trackpad's scroll leaves the motion running | `PadStops` |

## Secrets.tla: the secret dialog

`Secrets.tla` models the secret dialog (`docs/secrets.md`): an asker (a friend's AI through its driver, or the server's own sign-in) asks `nexus-server` for a secret for an account; the server mints a request id (durable, never reused across restarts) and puts the request, never a value, in the state every connected window receives; each window that can take requests shows a dialog for the oldest open one it has not answered; a person pastes the value once into one window, which sends it up its actions to the server alone, or presses Escape, which cancels it for every window; the server takes the first answer for an open request, writes the account's file and answers the asker `stored`, or answers `refused` with a reason (`busy`: one is already open, or a value held, for the account; `no-client`: no connected window can take one, none at all or only windows from before secret requests; `cancelled`; `timeout`; `malformed`: a value in `BadValues`, not of a token's shape). One chance (docs/secrets.md): the account's disk may fail (`DiskFails`, at most `MaxFailures` times) and heal (`DiskHeals`); a write while it fails may or may not land, and either way the value is held (`held`, state `holding`), not refused, and written again (`Retry`, `RetryFails`) until the write is durable, and only then is the asker answered `stored`. A request past its deadline ends `expired`, and an answer that crossed the deadline is still stored while its request is the newest of its account; at a restart, an expired request becomes `refused`, and a held value is lost (`lost`: the one documented window). `taken` is the value the server received for each request. An answer for a request no longer open is dropped and logged without its value. A restart drops every open request unanswered (its asker went with the server). A window that loses its link or quits loses its dialog and what was typed in it. A value is an opaque token (`Values`); `replies`, `transcript` (what the asker's session shows: its AI reads it back) and `log` (server.log) hold, for the last two, the lines the last step wrote, so an invariant on them covers every line ever written without the state growing with the history.

Invariants: `TypeOK`; `NoSecretToAsker`, `NoSecretInTranscript`, `NoSecretInLog`, `NoSecretToWindows` (no value in a reply, a session line, a log line, or any window's received state); `AtMostOneStored` and `StoredWhenStored` (one write per request, exactly when it ended stored); `OneOpenPerAccount`; `AnsweredOnce` and `AnsweredWhenEnded` (an asker hears exactly one answer for a request that ended stored or refused, none for one dropped at a restart); `ReceivedNeverDropped` (the owner's one-chance rule: a value the server received is stored, or held and being written again, or, after a restart, in `lost`; never dropped while the server runs); `StoredOnlyDurable` (`stored` only once the file holds the value); `HeldOnlyWhileHolding`; `NoMalformedStored`. Action properties: `ClosedStaysClosed` (an ended request never changes again: never satisfied late, never reopened, its id never reused; an expired one only to `stored` by its crossing answer, or to `refused` at a restart); `AskNeedsTaker`; `HeldOnlyStored` (a held value leaves only by being stored, or lost at a restart). Liveness, under fairness of deadlines, windows receiving the state, answers arriving, the disk healing and retries (never of a person answering): `EveryRequestEnds`, `DialogsClose` (every window's dialog for an ended request closes), `HeldIsStored` (a held value is stored in the end).

Instances, per commit: `MCSecrets.cfg` (two windows, one request, one restart: 2,355 states), `MCSecretsOne.cfg` (one window, two requests for one account: 3,763), `MCSecretsOld.cfg` (a window and an older one: 348). Nightly: `MCSecretsTwo.cfg` (one window, two accounts: 26,270), `MCSecretsWide.cfg` (two windows, two requests, one restart: 185,973) and `MCSecretsMixed.cfg` (a window and an older one, two accounts, two askers: 226,340). Witnesses (`WSec*`): `WSecReplyCarriesValue` (`NoSecretToAsker`), `WSecTranscriptValue` (`NoSecretInTranscript`), `WSecLogValue` (a late answer logged with its value: `NoSecretInLog`), `WSecRelayToWindows` (`NoSecretToWindows`), `WSecStoreTwice` (the latest paste wins: `AtMostOneStored`), `WSecLateStored` (an answer after a cancel or the deadline stored: `ClosedStaysClosed`), `WSecIdsReused` (ids counted in memory, from 1 after a restart: `ClosedStaysClosed`), `WSecTwoOpen` (`OneOpenPerAccount`), `WSecReplyTwice` (a late answer answered to the asker: `AnsweredOnce`), `WSecNoClientOpens` (`AskNeedsTaker`), `WSecNoTimeout` (`EveryRequestEnds`) and `WSecDialogStays` (a window keeps its dialog after another answered: `DialogsClose`), the last two as temporal violations. The one-chance rule's: `MCSecretsBad.cfg` (per commit: one window, one request, a value not of a token's shape, the disk failing once: 2,771 states) passes, and these are rejected, each also on `MCSecretsBad.cfg`'s own constants; `MCSecretsBadTwo.cfg` (the same with two requests, so a malformed paste is asked again and a crossing answer can be made stale by a newer request: 168,610 states, 57 s) passes nightly: `WSecDropOnFailure` (a value whose file cannot be written refused `unwritable` and dropped, as before the rule: `ReceivedNeverDropped`), `WSecLateAfterDeadline` (an answer that crossed the deadline dropped: `ReceivedNeverDropped`), `WSecStoredBeforeDurable` (`stored` answered for a write that did not land: `StoredOnlyDurable`), `WSecMalformedStored` (a paste not of a token's shape written: `NoMalformedStored`) and `WSecHeldNeverRetried` (a held value never written again: `HeldIsStored`, a temporal violation). At every step the walk also fails if a value's bytes are in a session line, any entry of the store, a log line, an answer, a diff sent to any window or an action's description. Seeds 1 to 4 run per commit, 2000 steps each (79 to 128 records: every seed asks, refuses busy, cancels, answers late, stores and times out; some seeds refuse no-client and drop at a restart). The binding is shown to fail twice: `--faulty-store-late` (seed 9, whose walk has late answers) writes an answer for a request no longer open to the account's file anyway, `--faulty-echo` puts a stored value in its log line; TLC must report `TraceMatches` violated. Liveness (`EveryRequestEnds`, `DialogsClose`) is the model's; the code's deadline is tested at its edge by `secrets_unit_desk`. What the model leaves out (the file's write, a crash at each of its calls, the modes) is `secrets_test files_crash` and `files_disk`.

## Running the checks

TLC needs Java 11 or newer and `tla2tools.jar`. The tests find the jar through `TLA2TOOLS_JAR`, and java through `JAVA` or `PATH`. Without `TLA2TOOLS_JAR` every `model` test fails and says what to set.

```sh
cmake -S . -B build
cmake --build build --target model_checks -j4
ctest --test-dir build -L unit
TLA2TOOLS_JAR=/path/to/tla2tools.jar ctest --test-dir build -L model -j "$(sysctl -n hw.ncpu)"
```

`-L model` matches two labels: `model` runs four instances (`MCWindowSprint`, `MCWindowEmpty`, `MCWindowNoSprint`, `MCWindow3Sprint`), the forty-eight witnesses, nine code traces (with the sprint tab first: seeds 1 to 5 on three friends, seed 6 on two friends and seed 8 on one, each 1000 steps, and seed 7 with no friends; without it: seed 9 on three friends), and the ten faulty traces; for the overlay, `Overlay.cfg`, its twelve witnesses, three code traces and two faulty traces; `model_nightly` runs the three largest instances, `MCWindow`, `MCWindow3` and `MCWindowLong`. CI's per-commit job runs `-L '^model$'` and the nightly workflow `-L '^model_nightly$'`: every property is still checked on every commit, on the smaller instances. Each TLC run gets its own directory under `build/tests/model/tlc/<test>/`, a copy of the models, its own `java.io.tmpdir`, two workers (eight on every instance but `MCWindowEmpty`, which ctest counts as eight of its `-j` slots) and a 60 second cap (300 on the nightly instances); its log is `tlc.log` there, and a trace run leaves its `WindowTraceData.tla` beside it.

One check by hand:

```sh
cmake -DWORK=/tmp/tlc-window -DMODELS=$PWD/models -DMODULE=MCWindow -DCFG=MCWindow.cfg -DEXPECT=pass \
      -P tests/model/tlc.cmake
```

## Adding the next layer's model

1. Extend `Window.tla`, or write a new module that extends it, with the new variables and actions. Keep refused operations as steps that change no model state and record the operation and its result in `last`.
2. State each operation's guarantee as an action property on `last'`, and the state rules as invariants. Add the properties to every config.
3. Add a witness per property: a module in `witnesses/` that passes one broken action to `NextWithAll` (widen it with the new actions), and a config that checks only that property. Register it in `tests/model/CMakeLists.txt` with the property it must violate, then read its counterexample and confirm it fails for the reason intended.
4. Teach `trace_walk.cpp` the new operations and their arguments, and `WindowTrace.tla`'s `Step` the new record kinds. Keep a faulty subclass that the trace check rejects.
5. Keep each instance small enough that TLC finishes in seconds; bound growth with a state constraint, not with guards in the actions.
